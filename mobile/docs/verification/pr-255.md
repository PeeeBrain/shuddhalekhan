# PR 255 iOS verification

Automated checks do not establish background execution on a phone. Device results below remain pending.

## Native contract ownership

Edit `KeyboardSessionProtocol.swift` and `KeyboardSessionChannel.swift` in `modules/shuddhalekhan-speech/ios/`, and `AgentActivityAttributes.swift` in `modules/shuddhalekhan-agent-activity/ios/`. The `with-shared-native-contracts` Expo plugin copies them into the extension target folders before Xcode project generation. Those outputs are ignored. Both the app's CocoaPods targets and extensions compile the same source contents. Missing inputs fail prebuild. Run prebuild after editing a contract if building directly in Xcode.

This removes the need to hand-edit two copies or compare them in the build script. The existing Swift protocol, TCP transport, listener, and lifecycle self-checks still run in the manual Mobile iOS build.

## Install and record evidence

- Download `Shuddhalekhan-unsigned-ipa` from the manual **Mobile iOS** run on `refactor/untangle-codebase`, matching the final PR commit.
- Install with iLoader using the same Apple ID and retaining both the keyboard and agent activity extensions. Avoid deleting the existing app so settings retention can be checked.
- Verify installed build **14**, device model, iOS version, artifact run URL and commit before testing. Build 14 alone cannot distinguish this artifact from an older build 14.
- If investigating a failure, start the filtered USB capture described in [the README](../../README.md#usb-logs-from-windows) before reproduction. Keep raw logs local and report timestamps and redacted phase logs.

## Required phone pass

1. **Settings retention.** Before changing providers, reopen existing saved settings. Confirm transcription and agent selections, keys, Google service account if configured, and MCP policies still work. Save, force-close, and reopen. Switching providers must clear the previous provider's secret; cancel unsaved edits and confirm saved settings remain intact.
2. **In-app Dictation.** With Agent Mode disabled, record, stop, and copy/share a transcript. Repeat with the configured remote provider. With Parakeet downloaded, use airplane mode and confirm on-device Dictation works. Cancel an utterance and confirm the next one works. Recording outside a keyboard session must stop when backgrounded.
3. **Background keyboard Dictation.** Start a session in the foreground, switch to Notes, choose Shuddhalekhan with Full Access, Dictate, speak, and Stop. Confirm recording acknowledgement, native transcription, and insertion exactly once at the cursor while the app stays backgrounded. Repeat a second utterance and repeat in a second host app.
4. **Session exits and recovery.** Cancel, hide/reopen the keyboard mid-utterance, stop/restart the session, and let the 10-minute session expire. Check expiry during an utterance and an audio interruption such as Siri or a call. The reason must be visible, the microphone must release, and a new session must work. Check the no-session Dictate path opens the app and resumes recording after returning.
5. **Agent Mode.** Configure the provider and a safe HTTP MCP tool. Speak a command from Home and from the background keyboard. Confirm prompts never insert into the host app. Approve one tool, deny another, and cancel while waiting. A stale approval must not execute a tool. Check a second command while busy, then Dictation after the run. Verify the Live Activity shows the session/run, approval notification opens the right request, final answer appears, and a saved answer restores after restart.
6. **Provider-specific checks.** Exercise each provider you have credentials for and record the others as untested. Check selected language reaches the provider, custom instructions affect Agent Mode, and disabling Agent Mode leaves Dictation working. Sarvam should auto-stop around 28 seconds; Google around 55. Desktop Managed Local is unavailable on iOS; Parakeet is the on-device path. iOS MCP supports HTTP bearer auth, not desktop stdio/OAuth.

Record each case as pass/fail/untested with provider, entry point, and timestamp. For startup checks, report cold tap-to-session-ready separately from repeat starts and Stop-to-insertion, separating permission prompts and model preparation. No performance improvement is claimed by this refactor.
